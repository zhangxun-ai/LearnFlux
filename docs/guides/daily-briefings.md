# 本机日报

工作台 `/briefings` 展示已生成的 AI 导游与微信日报，按期号日期切换、下载 Markdown，并可手动预览后保存到 Obsidian 或同步到飞书。生成流程和原有日程留在来源项目；页面刷新只读取已发布成品，不采集聊天、不调用模型、不触发收费服务。验证范围见[发布准备记录](../release-readiness.md)。

## 阅读与期号

页面沿用工作台的草绿色 `natural` 主题。头部只保留标题、类型切换、日期、刷新和保存菜单，不再重复展示口号、“最新”标签或日期。AI 推荐先给 `why_worth_attention`（与用户工作的关系），再给摘要、影响判断的阅读边界和直达原文入口；详细解读和 15 组来源检查记录折叠展示。微信内容去除重复导航时保留群聊、私聊、出处和覆盖限制。

两类日报统一按 `edition_date` 选择期号。来源生成器写入 `edition_date`、`content_start`、`content_end` 和带时区的 `generated_at`；内容窗口和生成时间不替代期号。旧 bundle 由 `briefings/bridge_runner.py` 适配：微信 bundle 前缀是内容日，期号为次日；AI bundle 前缀已是期号。缺失生成时间时可从 bundle 的生成时间段补读，不能使用文件修改时间或当前日期。manifest 的显式期号若与 bundle 身份冲突则拒绝读取；历史 manifest/hash 和 bundle 名不为显示统一而改写。

例如，微信 `2026-10-30-live-…` 与 AI `2026-10-31-daily-…` 同属 2026-10-31 期。Markdown 正文标题、下载文件名、同步预览标题和 Obsidian 文件名均使用这一期号，微信仍保留内容日期说明。飞书显示标题也用期号，但持久去重 key 继续使用旧 bundle 前缀日期（微信为内容日），防止升级后重复建文档。

`/briefings?kind=ai&date=2026-10-31` 和 `kind=wechat` 可直达指定类型与期号。指定期号尚未生成时显示明确空态；切换类型仍保留该期号，不拿旧报回填。未指定日期时才使用可用期号列表的默认选择。

## 配置与边界

复制 `config/briefings.example.json` 到私有的 `data/briefings/integration.json`，填写来源目录和工作台既有账户的 `user_id`，再启用。也可用 `LEARNFLUX_BRIEFINGS_CONFIG` 指向私有配置。配置应设为仅本人可读，不能提交。Obsidian 复用工作台 `obsidian` 配置，飞书复用 `LEARNFLUX_FEISHU_ARCHIVE_CONFIG` 或既有归档配置；飞书账户名称必须对应同一个已启用的日报所有者。

日报接口同时校验现有登录、配置的所有者、本机连接和请求来源。远程域名、局域网访问及其他工作台账户不能读取日报。页面本身只是空壳；正文、原文、图片和导出都走同一鉴权。响应禁止缓存，正文禁用脚本、外部资源与表单。公开来源链接可在新窗口正常打开。

`briefings/bridge_runner.py` 用来源项目的 `runtime/bin/python` 读取已经发布的 bundle。微信复用来源项目 `daily_publish.DailyStore` 的实时授权范围与文件 hash 检查，读取后再查范围；不复制简化的授权规则。AI 成品也验证 manifest/hash。只允许 report.html、report.md，以及微信 sources.html 和列入清单的 media 图片。拒绝符号链接、越界路径、非成品文件及超大文件。

来源目录需保留原有 `tools`、`runtime`、`state`、`exports` 等依赖。工作台不连接独立展示端口，因此原来的 52634/52635 展示服务是否运行不影响本页。原服务和历史成品不自动删除。

## 手动同步

预览为只读操作。确认时重新校验原文与预览摘要；微信另需明确私人内容确认。仅保存日报 Markdown，不复制完整聊天原文页和图片；本机来源链接转换为保留发言人/时间等标签的本机查看提示，公开链接保留。

- Obsidian：保存至 `日报/AI 导游日报/` 或 `日报/微信日报/`，文件名含日期与内容摘要。完整文件原子落盘，同一内容不重复写入；已有用户修改时返回冲突，绝不覆盖。
- 飞书：复用 `exports/feishu.py` 的身份、修订、未知创建核对与正文回读能力，独立状态库 `data/briefings/feishu.db`。同类型同日期更新同一文档，旧版本不能覆盖新版本，远端人工修改保留。只有回读与本次预览版本都匹配才显示成功；不确定状态不盲目新建。

来源生成沿用既有的两项每天 9 点 heartbeat；V2 只更新这两项提示，没有新建日程，也没有无人值守首跑成功的证据。工作台没有自动外发日程。关掉私有配置的 enabled 即可停用读取和同步，不改来源成品或已同步笔记。

## 验证

在仓库根目录运行：

```bash
uv run --extra dev pytest tests/unit/test_briefings.py -q
uv run python scripts/sync_product_navigation.py --check
```

离线检查覆盖所有者与本机限制、来源范围变化、文件完整性、脚本过滤、预览只读、同步确认、防覆盖和历史期号适配，不读取真实聊天或发送日报。该模块包含在 2026-11-03 的默认离线检查中；完整结果与未验收事项见[发布准备验证](../release-readiness.md)。

首次启用时，先核对本机来源项目的身份、授权范围及一份已发布报告，再检查页面预览；要保存或同步时按实际目标确认。源码与演示截图不附带私有来源项目、聊天成品或已配置的定时任务。
