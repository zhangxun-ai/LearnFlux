# 手动 AI 图解

结果页、学习页和图解工作台共用图片生成组件。默认根据整篇内容生成，未生成时只显示“生成图解”；生成后以图片为主，保留放大、下载、修改与历史版本。页面加载、切换视图和刷新不调用模型。

## 最简生成流程

- 原文能完整放入绘图提示词：直接生成一张图片，保存后完成，只调用一次生图模型。
- 原文超过绘图输入预算：优先一次全文提炼，再生成一张图片，保存后完成。绘图方案包含主线、关键事实、原文案例及必要限定。
- 只有带段号的完整原文超过 `single_pass_chars` 时，才使用有限并行分段与一次综合；不静默截断正文。
- 原文、范围、内容要求、规划模型与提示词版本一致时，重新生成可复用已保存的方案，不重复提炼。内容或要求变化时重新规划。
- 修改短文图片直接输入原图、完整原文和修改意见。长文修改需要重新提炼时，以原方案为基线，只调整相关内容。

没有生图后看图检查，也没有可选检查入口。图片生成并保存成功即为任务完成；保留本地文件有效性检查、权限校验和请求去重，它们不调用模型。旧版本的检查记录只保留在历史存储中，不展示、不重新执行；旧 `review_enabled` / `review_model` 配置被忽略。

## 质量放在生成前

直接生成和长文生成都使用简短的中文绘图要求：核心关系作为主视觉，原文案例帮助理解，短标签和清楚的主次层级，保留必要数字、条件与观点归属。并列分支不画成串行，材料未给出的日期、答案和效果承诺不补造。美术与构图保持自由，沿用认可的暖色插画方向，不固定卡片数。

长文提炼只传正文和修改要求，不携带任务ID、队列状态、旧文字摘要或重复章节目录。生成提示词只包含紧凑简报、相关原文摘录、美术方向与本次修改意见，不再携带历史检查长文。原文、段落位置与完整方案保留在后端，以便追溯。

提示词版本为4。方案缓存按原文哈希、范围、内容要求、模型和提示词版本区分，旧版方案不会被错误复用。已有图片不覆盖。

## 配置与数据

`main.py` 从项目 `.env` 加载 `OPENAI_API_KEY`，部署环境变量优先，密钥只在后端读取。配置示例见 `config/config.example.jsonc`；缺少密钥时生成入口不可用。客户端固定使用 OpenAI 官方地址，SDK 自动重试为零，不继承文字解读的转发地址。

默认 `gpt-image-2`、`high`、`1536x2048`；长文规划默认 `gpt-6-luna`。`single_pass_chars` 默认200000，统计含段号的原文长度；`chunk_chars` 默认12000，`planning_workers` 默认3（1～4），仅用于超出单次预算的原文。自定义规划模型时应按其上下文容量配置输入预算。原文上限默认200000字符，超过时明确拒绝而不截断。

风格参考位于 `image_diagrams/assets/`，来源记录在 `provenance.json`。参考图只决定美术方向，不作为新内容的事实依据。旧知识手绘版本仍能查看、下载与修订。

图片、原文快照、请求、提示词、方案和用量保存在 `data/image_diagrams/<job-id>/`，不属于ASR临时清理范围。SQLite或已配置的PostgreSQL保存任务和版本；备份须同时覆盖数据库与图片目录。容器部署应挂载持久卷，本功能没有自动同步图片到R2。

读取原文、方案、任务和图片前检查来源归属与账号状态，飞书来源还检查本机账号所有者。图片通过有身份校验的接口提供，不放入公开静态目录。优先用完整校对原文，否则使用已有原文；不会隐式下载媒体、调用ASR或重跑文字解读。

## 进度、恢复与费用

页面只显示“准备内容 → 绘制图解”两阶段和已用时间。全文提炼时不制造分段或完成百分比；真正分段时显示已完成段数。绘图耗时不可预测，使用不定进度动效，不显示预计剩余时间。图片保存后进度收起。减少动态效果、页面隐藏和离开视口时均暂停循环移动。

状态为 `queued → planning → generating → succeeded`，失败为 `failed`，图片请求已提交但结果无法确认时为 `unknown`。后台线程独立于浏览器；刷新可继续查看。重启可恢复排队和未提交图片的过期工作，已提交且结果不明不会自动重发。历史 `reviewing` 有图片时按完成展示，不调用检查模型。

同一请求标识严格幂等，同一来源只允许一个活动任务；重复点击不重复生图。每日上限按 `Asia/Shanghai` 自然日计算，保守计入新尝试。规划与生图用量分开记录，不推断赠送额度余额或编造费用。无任务时后台不调用OpenAI。
