# 接入微信日报与 AI 导游：给 Agent 的提示词

这份提示词先核对来源项目和权限，再接入工作台。它不是开箱即用的微信采集器，也不会把维护者的私人日报或定时任务复制给你。

```text
请帮我在自己的 LearnFlux 中接入微信日报与 AI 导游，完成“自己的来源 → 报告生成 → 工作台阅读”的流程。

先阅读 README、AGENTS.md、docs/guides/daily-briefings.md、config/briefings.example.json，以及 src/video_transcript_api/briefings/bridge_runner.py 和 service.py。

1. 先确认我需要微信日报、AI 导游中的哪一种或两种、感兴趣的主题、允许读取的来源、所属账号，以及希望每天什么时候运行。微信只处理我明确授权的群聊/私聊范围，不默认读取全部聊天；公开 AI 来源也由我选择。真实姓名、群名、聊天和凭据不进入 Git、日志、截图或聊天回复。
2. 检查本机是否已有与当前桥接兼容的外部来源项目及其 tools/runtime/state/exports。LearnFlux 仓库只提供读取和接入，不附带外部报告生成项目或微信数据。若缺少兼容生成器或授权，明确列出缺项与可行选项，不编造报告，不假装创建两个定时任务就能自动采集微信；新增生成器属于额外实现，先说明范围，不擅自开发。
3. 如果已经具备来源，复用现有配置与定时任务，先检查目标期号是否已有完整成品。需要生成时先在我同意的来源和费用范围内手动运行一份，检查摘要与原文相符、日期正确、来源可追溯；AI 导游说明与我当前工作的关系，区分事实和判断，不把来源日期未知写成没有更新。不重复生成或通知同一份成品。
4. 手动成品验收通过后，再由我确认各自的执行时间和任务范围；已有 Codex 任务直接复用，无任务再按当前应用能力创建独立任务。两类日报各自完成，不互相等待。依赖本机文件时说明电脑和桌面应用需保持运行。创建或启用不代表无人值守已跑通；至少检查一次实际定时运行结果，未到运行时间时标为未验证。
5. 将 config/briefings.example.json 复制到受 Git 忽略的私有配置位置，设置 source_root、已有 owner_user_id 和 enabled；保留权限和历史数据。使用需要的 LEARNFLUX_BRIEFINGS_CONFIG 私有路径，禁止把来源路径、账号或聊天数据写进公共模板。按当前脚本使用 server.sh 管理工作台，不重复启动、不未经同意中断已有任务。
6. 在本人账号下通过本机地址打开 /briefings，分别检查所选类型、真实期号、完整正文、原文入口、历史与 Markdown 下载。刷新只重新读取成品并保留当前期号，不代表生成或自动跳到最新一期。远程域名和局域网访问当前不支持。示例截图、空页面或模拟数据不作为真实接入成功证据。
7. 只有我需要外部保存时才配置 Obsidian/飞书；先预览目标与正文，由我确认，微信摘要还需确认私人内容。仅保存日报 Markdown，不默认同步完整聊天原文、图片或自动外发。已有笔记、远端人工修改与未知写入状态按指南保护。

最后分别列出来源/授权、手动报告、定时运行、工作台阅读、下载和可选外部保存的已通过/未通过/未验证状态；给出本机操作步骤与停用方法，不公开私人原文或访问令牌。缺依赖时继续可独立完成的检查，但如实保留未完成项，不替我提交或推送代码。
```

完整接入、期号与隐私边界见[日报指南](../guides/daily-briefings.md)。
