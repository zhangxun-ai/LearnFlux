# 接入 AI 导游与微信日报的 Agent 提示词

两类报告可以独立配置。先打开 LearnFlux 所在的本地项目，把对应代码块发给能访问本机目录的 Agent。只跑 AI 导游时只需提供公开来源，无需微信。

## AI 导游

```text
请帮我把 AI 导游接到本机 LearnFlux，完成一次真实试跑，再按我确认的时间设置 Codex 桌面端定时任务。先读 AGENTS.md、docs/guides/daily-briefings.md 和 src/video_transcript_api/briefings/bridge_runner.py。

1. 先问我正在做什么、希望关注哪些主题、想跟踪哪些公开来源和每天几点运行。可先从 3–5 个官方博客、作者 RSS 或访谈栏目开始，例如 OpenAI、Anthropic、Latent Space；使用前核对真实可访问的订阅或栏目链接。以北京时间昨日 00:00 至今日 00:00 为默认内容窗口，今日期号。保存来源清单、关注主题和编辑规则在我的私有本地项目里，供每次运行复用。
2. 如已有兼容的 WeChatLocalVault 来源目录，复用其 runtime、tools 与 AI 发布器。按该项目 tools/ai-guide-retrieval.md、tools/ai-guide-publish.md，用 ai_guide_check.py --date <内容日> --fetch-content 取候选和正文，按发布器要求生成审阅 JSON，再用 ai_guide_publish.py build --review <审阅文件> 生成成品。全新安装只有 AI 导游时，可按日报指南的公开来源目录契约，在私有目录创建 Python 环境和可复用的本地成品生成步骤，复用已有日报来源时不要切换根目录或覆盖成品。
3. 每个来源记下检查结果，按真实发布日期判断是否在窗口，按 URL 或视频 ID 去重。读完原文或可核对的完整字幕才做主推荐。每条保留来源名、日期、原文链接、摘要、阅读依据，以及与我正在做的事的关系。区分原文事实和 Agent 判断。遇到限流、仅有标题或日期无法确认时，记录缺口。当天没有值得推荐的内容时可交付短报。
4. 用我认可的一组公开来源生成一期，先确认当天是否已有完整成品。根据指南填写私有 integration.json，以原有网页身份在本机 /briefings 选择 AI 导游和正确期号。检查 HTML 正文、原文链接与 Markdown 下载，缺失期号应显示空态。只有微信尚未配置时，微信来源提示可单独处理。
5. 手动通过后，在 Codex 桌面端用能访问同一来源目录的本地项目设置一项独立的「AI 导游」日程，复用已有同类任务。将日期窗口、来源、发布及验收步骤写入任务说明，核对 Scheduled 中的运行位置、时区与下次触发。检查第一次实际定时运行再确认无人值守可用；若尚未触发，分别报告手动验证和定时状态。费用与外部发送另行授权。
```

## AI 微信日报

```text
请帮我把 AI 微信日报接到本机 LearnFlux，完成一次真实试跑，再按我确认的时间设置 Codex 桌面端定时任务。先读 AGENTS.md 和 docs/guides/daily-briefings.md。

1. 先确认我的系统、微信是否已在本机登录、已有日报来源项目路径，以及我明确允许读取的群聊与私聊。给我一份会话范围供确认，再读消息。用北京时间已结束的一个内容日试跑，期号为次日。先说明聊天正文将在哪个模型或 Agent 环境中处理，私聊正文、图片和语音的外部传输要有我的明确授权。
2. 核对来源是否提供兼容的 WeChatLocalVault 运行环境、实时读取器、发布器和当前会话策略。优先复用已有来源。若缺少来源项目或当前微信版本无法只读采集，请明确告诉我缺哪个安装包、权限或支持条件；向我索取可信来源的兼容项目，勿安装来历不明的读取器或绕过登录与范围校验。
3. 在兼容来源项目目录按 tools/live-daily-input.md，用 runtime/bin/python tools/live_daily_input.py --date <内容日> 采集，核对授权范围、覆盖与输入清单。已获授权且本机语音工具可用时，按 tools/daily-voice.md 执行 daily_voice.py enrich --input <输入目录>，后续审阅用它返回的目录。对当天活跃的每个已选会话交代重点或无值得提炼事项，给出会话、发言人、时间和来源，区分消息事实和判断。缩略图只按可见内容描述。对无法读取的分表、会话、语音或图片写清缺口，保留旧成品，避免将缺失消息写成没有消息。
4. 按 tools/daily-publish.md 生成审阅 JSON，用 runtime/bin/python tools/daily_publish.py build --input <输入目录> --review <审阅文件>。先检查目标期号是否已通过校验；发布是写本机成品。按指南连接 LearnFlux，用原有网页身份打开 /briefings 的微信日报，检查期号、选定会话覆盖、原文回查与 Markdown 下载。校验失败时保留原报告，修复输入后再试。
5. 手动通过后，在 Codex 桌面端用可访问原目录的本地项目设置一项独立的「微信日报」日程，复用已有同类任务。记录会话范围、日期窗口、发布和验收步骤，回读运行位置、时区、下次触发与首次实际运行结果。电脑、微信及 Codex 需满足本机采集与调度条件。只在本机保存报告，保留聊天资料与既有配置；外发、上传、付费转写需我另外授权。
```
