# 首页重设计 — 内容解析工作台

- 日期：2026-06-09
- 目标：把首页从"只支持在线视频链接 + 杂乱历史"，重设计为支持 4 类输入 + 清爽历史的统一工作台。
- 原则：复用现有 app.js 机器（URL 提取/排序/选择、token、提交、轮询、历史存储），只做加法与重排，不碰视频后端链路。低耦合：新组件样式独立放 `workbench.css`。

## 底层思路

4 个需求 = 2 种交互 × 2 种内容：

| | 在线（链接） | 本地（上传） |
|---|---|---|
| 视频/音频 | ①视频链接 ✅ | ②上传视频 🚧 |
| 帖子/文档 | ③帖子链接（X✅ / 小红书·公众号🚧） | ④上传文件 🚧 |

收敛为两个输入 Tab：**🔗 粘贴链接**（智能识别并路由）+ **📁 本地文件**（拖拽上传）。

## 输入区

- **链接 Tab**：一个智能框，复用既有 URL 提取/选择；新增「识别横幅」实时显示"将执行什么"（视频→转录 / 𝕏→帖子精华 / 公众号→即将上线）。
- **识别单一事实源**：`classifyContent(url)`（app.js）同时驱动识别横幅、提交路由、历史分类。精确主机名匹配，避免 `netflix.com` 误判为 `x.com`。
- **上下文选项**：说话人识别 / 评论洞察仅在识别为视频时显示，平时收起降噪。
- **提交路由**：X 帖子 → 跳 `/post`；`soon` 平台（公众号）→ 友好"即将上线"提示；视频/未知 → 既有转录流程。
- **本地文件 Tab**：拖拽区 + "🚧 即将上线"，点击/拖放给明确提示，不做假流程。

## 历史记录（修复"乱"）

- 统一卡片：类型徽章（视频/帖子/文件）+ **状态徽章**（已完成/处理中/失败/已提交，配色）+ 标题 + **只显域名**（不再铺长 URL）+ 相对时间 + 特性标签 + 操作。
- **类型筛选 Tab**：全部 / 视频 / 帖子 / 文件；空分类显示空状态。
- **日期筛选下拉**：全部时间 / 今天 / 近 7 天 / 近 30 天 / 近 90 天。
- **最新靠前**：渲染前按 `timestamp` 倒序（不依赖存储顺序）。
- **分页**：每页 8 条（`HISTORY_PAGE_SIZE`），上一页/下一页 + "第 X/Y 页 · 共 N 条"，仅超过一页时显示；存储上限由 10 提升到 200。
- 渲染流水线：`getHistory → 类型+日期过滤 → 倒序 → 分页切片 → buildHistoryCard`；筛选/翻页改变状态后重渲染。
- 状态最佳努力刷新：视频任务复用既有 `getTaskStatus` 异步更新徽章（容错字段名）。
- 操作：视频→查看(/view)；帖子→重新分析(/post?url=)；通用→复制 / 删除。

## 已建 vs 待建（逐步实现）

✅ 已建并验证：布局、两 Tab、识别横幅、上下文选项、X 帖子路由、历史卡片重做 + 类型筛选 + 空状态、视频状态最佳努力刷新、响应式。
🚧 待建（UI 已就位，点击有"即将上线"提示）：
1. 本地视频/音频上传 → 转录（需后端上传端点 + 任务接入）。
2. 本地文件上传 → 解析。
3. 小红书图文帖子、微信公众号文章 → 帖子洞察（沿用 post-insight 管线，新增 fetcher + 平台识别；公众号留言抓取是已知难点）。
4. 帖子洞察结果写入首页历史（需统一 localStorage 历史的存储/加密兼容）。
5. 历史状态全量实时轮询（当前为打开页面时最佳努力刷新一次）。
