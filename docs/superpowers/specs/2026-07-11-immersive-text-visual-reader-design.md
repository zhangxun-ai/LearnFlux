# 文字 / 图解沉浸阅读器设计

## 目标

把当前“原解读与图解连续堆叠”的展示改为同一套全屏沉浸阅读器：文字和图解一次只显示一种，用户可以在不离开当前章节的情况下快速切换。该阅读器同时服务于全系列解读和单节解读页。

验收标准：

- 不再显示 YAML front matter、Markdown 围栏或孤立的 `---` 等格式噪音。
- 全系列阅读时，文字与图解是两个互斥页面，不再上下或左右同时展示。
- 阅读器占满可用内容区，仅保留薄顶部栏和章节导航。
- 单节解读页提供“一键图解”，首次点击才生成，之后可在文字和图解之间即时切换。
- 切换模式时保持当前小节；关闭阅读器后回到原页面位置。

## 已确认的产品方案

采用原型 A：全屏沉浸阅读器。

顶部栏从左到右仅包含：返回、当前集合/单节标题、`文字解读 / 图解` 分段开关、必要操作（主题、重新生成、导出）。正文区域一次只渲染一个模式。桌面端隐藏工作台侧栏和元数据卡，移动端顶部栏允许换行但仍保持单列正文。

## 信息架构

### 全系列入口

集合页继续保留“全系列解读”和“图解”两个入口，避免破坏现有认知。任一入口进入沉浸阅读器后，都使用同一内容状态：

- 从“全系列解读”进入时默认打开文字模式。
- 从“图解”进入时默认打开图解模式。
- 顶部开关可即时切换，不返回集合工作台。
- 章节轨道包含“全局”和稳定的 `section-XX` 小节。切换模式时仍停留在同一项。
- 全局文字显示清理后的全系列解读；全局图解显示 overview。
- 小节文字显示该 section 的原解读；小节图解显示 full_note 中同 ID 的 page。
- 复习题只在图解模式末尾提供一个独立“复习”入口，不重复插入每个小节。

集合工作台内不再直接渲染完整双层长页面，只显示简洁入口、生成状态和“进入沉浸阅读”按钮。

### 单节解读入口

在现有单节解读页“内容总结”区域增加“一键图解”按钮和“沉浸阅读”入口：

- 进入后默认保持用户点击时的模式。
- 文字模式复用当前 `ai.overview`，不生成第二份解读。
- 主按钮“一键图解”只请求 `overview`，首次点击最多发起一次 overview 生成；后续直接复用成功版本。
- 图解模式提供次级操作“生成逐段图解”，仅在用户明确点击时请求 `full_note`。不得在打开阅读器或点击“一键图解”时并行生成 full_note。
- 如果已有 full_note，则允许在章节轨道中切换该单节内部的解读小节；否则先展示 overview，并保留“生成逐段图解”的唯一入口。
- overview 与 full_note 各自只由对应按钮触发、独立显示状态并独立重试。
- 关闭后恢复到原解读页的滚动位置。

## Markdown 噪音治理

问题根因不是字体样式，而是集合总结的 YAML front matter 被解释为第一个解读 section；共享图解渲染器又逐行把它当正文输出。因此需要在数据边界清理，而不是用 CSS 隐藏。

清理规则：

1. 去除 UTF-8 BOM 和包裹整份内容的 Markdown 代码围栏。
2. 仅去除文档开头成对的 `--- ... ---` YAML front matter。
3. 保留正文中的合法水平分隔线。
4. 处理后的 Markdown 再进入 section 拆分、source hash 和前端安全渲染。
5. 前端共享 Markdown 渲染器保留一次防御性清理，避免旧缓存文档继续显示噪音。

现有文字内容不重写、不摘要，只去除结构性元数据。

## 组件边界

### 共享阅读器

在 `visual-learning.js` 中增加可复用的沉浸阅读器渲染契约，输入包含：

- 当前模式 `text | visual`
- 当前 section ID（空值表示全局）
- 清理后的 interpretation sections
- overview 与 full_note 文档
- 状态、主题及回调

共享组件只负责布局、切换和渲染，不负责 API 请求。集合页和单节页各自继续管理鉴权、生成、轮询和引用跳转。

### 页面集成

- `collections.js` 负责将集合 summary、interpretation sections 和视觉文档适配到共享阅读器。
- `study.js` 负责将当前 `ai.overview`、study interpretation sections 和视觉文档适配到共享阅读器。
- 两个页面使用各自现有 dialog/fixed-layer 容器，但共享相同 CSS 类和交互语义。

## 状态与错误处理

- 文字始终优先可读，不等待图解生成。
- 图解未生成时只在图解页面显示生成进度；切回文字不受影响。
- overview 与 full_note 继续独立失败、独立重试。
- 切换集合、关闭阅读器或离开页面时停止对应轮询，避免旧结果污染当前内容。
- 旧 overview 若 stale，可带“旧版”标记继续展示并后台生成新版本。
- stale full_note 不得与当前 interpretation sections 按 `section-XX` 强行配对；在新版成功前，只展示当前文字并提示“逐段图解正在更新”。这样避免 front matter 清理后 section 拓扑变化造成错节配图。
- 集合页每次切换集合或重新打开阅读器都会递增 `readerGeneration`。所有 GET/POST 返回只有在 `collectionId + readerGeneration` 仍与当前阅读器一致时才允许写入状态和 DOM；单节页使用 `viewToken + readerGeneration` 执行同样校验。关闭阅读器或切换 owner 会使所有在途响应失效。

## 视觉与可访问性

- 正文最大宽度约 920px，图解最大宽度约 1180px，居中展示。
- 顶部栏 sticky；正文是唯一主要滚动区域。
- 模式开关使用 `role=tablist`，章节使用可聚焦按钮，支持键盘操作。
- `Esc` 关闭阅读器，焦点返回触发按钮。
- 尊重 `prefers-reduced-motion`，不强制平滑动画。

## 验证范围

只覆盖必要主路径：

1. front matter 清理后不再产生 `---` section，正文水平线仍保留。
2. 全系列文字/图解互斥显示，切换保持 section ID。
3. 单节“一键图解”首次只请求一次 overview；只有“生成逐段图解”请求 full_note，成功后均即时复用。
4. overview/full_note 独立状态与重试不回归。
5. 生成中快速切换集合时，迟到响应不能覆盖当前集合阅读器状态。
6. 桌面真实集合和一个真实单节解读页完成浏览器验收：空间占用、键盘关闭、模式切换、控制台无错误。

不增加与本次交互无关的边界测试，不修改生成模型、数据表结构或现有解读内容。
