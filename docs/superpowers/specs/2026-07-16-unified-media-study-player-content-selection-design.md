# 统一音视频边播边学：真实内容选择与播放器接入设计

## 1. 文档状态

本规格描述已经确认的正式产品行为，取代此前“仅展示 UI、不接真实数据”的预览范围。

此前的静态预览仍可作为视觉参考，但最终产品不再显示四个“单个视频 / 单个音频 / 合集视频 / 合集音频”演示按钮，也不再把 `/static/study-player-preview.html` 作为正式入口。

## 2. 目标

把本地单个音视频、已有合集和新建本地合集统一接入“边播边学”流程，让用户可以：

- 选择已经解析且仍可播放的单个音视频。
- 选择已有音视频合集，并在播放器内通过紧凑下拉列表切换分集。
- 直接选择尚未解析的本地音视频，立即播放，同时在后台上传、转录和生成 AI 解读。
- 直接选择文件夹或多个音视频创建合集，立即播放第一集，同时后台处理全部分集。
- 播放时常驻查看同步逐字稿，并按需打开 AI 解读或提问。

所有改动必须保持现有单篇解读、系列深度学习、`/view/{view_token}`、转录和导出行为不变。

## 3. 已确认的产品决策

1. 采用统一内容选择页，不使用弹窗，也不新建完整媒体资料库。
2. 正式入口位于当前项目服务的 `/study`，不是独立视觉稿端口。
3. 内容选择只分“单个内容”和“合集内容”；音频或视频由系统自动识别。
4. 单个内容同时支持已有内容和新的本地文件。
5. 合集内容同时支持已有合集、选择文件夹和选择多个文件。
6. 新本地内容选中后立即进入播放器；上传和解析不阻塞播放。
7. 已解析但源文件丢失、已清理或无法实际播放的历史内容不显示在选择器中。
8. 播放进度第一版保存在当前浏览器，不新增数据库字段。
9. 从单篇历史卡片或合集源详情进入时跳过选择页，直接打开对应内容。

## 4. 页面与路由

### 4.1 `/study`：正式内容选择页

侧栏“边播边学”链接改为 `/study`。页面使用现有应用外壳，并包含：

- “单个内容 / 合集内容”两个页签。
- 标题、作者或合集名称搜索。
- 单个页签中的“选择本地音视频”和真实最近内容列表。
- 合集页签中的“选择文件夹”“选择多个文件”和真实合集列表。
- 已就绪、解析中、失败等真实状态。

选择真实内容后，当前页面切换为播放器状态，不先经过另一张静态中间页。

### 4.2 统一播放器路由

同一套播放器页面支持两种不含糊的正式地址：

- 单篇：`/study/{view_token}`。
- 合集分集：`/study/collections/{collection_id}/sources/{source_id}`。

合集地址必须包含 `collection_id` 和 `source_id`，不能只靠 `view_token` 推断合集。因为同一 `view_token` 可能被多个合集复用，仅凭它无法唯一决定合集、分集顺序和播放进度键。

播放器页面布局升级为已确认的统一播放器：

- 左侧媒体区。
- 媒体画面下方固定当前字幕条，不覆盖视频。
- 右侧常驻同步逐字稿，当前段高亮。
- AI 解读和 AI 提问按需展开。
- 合集内容显示紧凑选集下拉框、上一集和下一集；单个内容完全隐藏合集控件。

已有 `/view/{view_token}` 继续作为原解读页，不被播放器替换。

### 4.3 上下文入口

- 单篇历史卡片：仅当内容为音视频、拥有 `view_token` 且源文件仍可播放时显示“边播边学”，链接到 `/study/{view_token}`。
- 合集源详情：仅当源为音视频且文件仍可播放时显示“边播边学”，链接到 `/study/collections/{collection_id}/sources/{source_id}`。
- 上下文入口直接打开播放器，不显示 `/study` 内容选择页。
- `/api/audit/history` 和合集 source 详情响应分别增加服务端计算的 `study_available` 与 `study_url` 字段；前端只按这两个字段显示入口，不逐卡请求、不自行猜测文件是否可播。

## 5. 组件边界

### 5.1 内容库读取层

新增一个只读的 Study 内容库接口：

`GET /api/study/library?kind=single|collection&q=&limit=&offset=`

按 `kind` 返回当前用户可归属、且至少有一个真实可播放音视频源的内容。单篇响应示例：

```json
{
  "items": [
    {
      "view_token": "...",
      "title": "访谈.mp3",
      "source_kind": "audio",
      "media_type": "audio/mpeg",
      "state": "ready",
      "progress": {"percent": 100},
      "transcript_count": 682,
      "ai_ready": true,
      "created_at": "..."
    }
  ],
  "total": 1
}
```

实现约束：

- 单篇复用审计记录中的 `user_id + task_id` 归属关系，不能直接向所有已认证用户暴露 `task_status` 中的全部任务。
- Study 上传和单篇重新解析必须补充包含 `user_id`、脱敏 API Key 和 `task_id` 的审计记录，使新任务能进入当前用户的内容库。
- 普通转录任务只有在保留了实际可播放源文件时才进入内容库。
- 无法证明归属的旧 Study 上传不自动暴露；用户可以重新选择原文件。不要用“本地部署”作为绕过归属校验的理由。
- `q` 对单篇标题/作者、合集标题/创建人做模糊匹配；`limit`、`offset` 和过滤在服务端完成，前端不扫描全部历史记录。

### 5.2 合集读取层

已有合集数据和页面继续复用，但为 `learning_collections` 增加可空的 `owner_user_id`：

- `GET /api/collections`
- `GET /api/collections/{collection_id}`
- `GET /api/collections/{collection_id}/sources/{source_id}`

归属和迁移规则：

- 创建新合集时，服务端从认证上下文写入 `owner_user_id`，不接受客户端传入 owner。
- 单用户回退模式下，迁移时把所有 `owner_user_id IS NULL` 的旧合集归给 `legacy_user`，保持现有本地使用体验。
- 多用户模式下，无法证明归属的旧合集保持原数据不删除，但不进入任何用户的内容库，也不能通过 Study 播放器读取；后续由管理员显式分配，不在本功能中猜测归属。
- 新增 owner 后，所有合集接口都按当前 `user_id` 过滤或断言归属；这明确包括列表、`filter-options`、详情、source、上传、重试、取消处理、摘要、知识图谱、导出、文件读取和 `reveal`。`filter-options` 只从当前用户的合集聚合选项；取消处理和 `reveal` 必须先断言 owner。越权统一返回 404，避免泄露资源存在性或触发其他用户的任务/本机文件操作。

选择页通过 `GET /api/study/library?kind=collection` 获取可播放合集，不在前端拉取全部 `/api/collections` 再过滤。合集卡片显示真实分集数、处理状态，并在前端合并浏览器内保存的上次播放位置。

### 5.3 统一媒体源解析层

扩展 Study 媒体源解析，使其能够安全读取：

1. 当前 `study_uploads` 中的 Study 文件。
2. `task_status.source_file_path` 指向、且位于配置允许目录内的保留源文件。
3. 合集上传保存的本地音视频。

所有文件路径必须在配置的源文件根目录或明确允许的临时目录内完成解析和校验，不能接受客户端提交的任意磁盘路径。

媒体文件不能依赖原生 `<audio>/<video>` 请求携带 `Authorization` 请求头，也不能把长期 API Key 放进 URL。采用短时签名媒体凭证：

1. 前端用 Bearer 认证请求单篇 Study session，或请求带合集上下文的 Study session。
2. 服务端先执行归属校验，再在 session 响应中返回短时 `media_url`。
3. 单篇地址形如 `/api/study/{view_token}/source-file?media_token=...`；合集地址形如 `/api/study/collections/{collection_id}/sources/{source_id}/source-file?media_token=...`。
4. `media_token` 是服务端签名的短时能力凭证，只绑定 `user_id`、内容标识和过期时间；它不是 API Key，不能用于其他接口。
5. 媒体端点校验签名、过期时间、内容标识和当前文件安全路径后返回文件，并支持浏览器 Range 请求。凭证过期时前端重新请求 session 获得新地址。

媒体响应使用 `Cache-Control: private, no-store`，页面使用不泄露完整查询串的 Referrer Policy。源文件缺失或凭证无效统一返回稳定错误，不回显磁盘路径。

### 5.4 统一归属校验

新增一个服务端 Study 访问判定入口，所有播放器相关接口必须复用它，不能各自只检查“token 是否存在”：

- 单篇：审计记录必须证明当前 `user_id` 拥有该 `view_token` 对应的 `task_id`。
- 合集：`owner_user_id` 必须匹配当前用户，且 `source_id` 必须属于 `collection_id`；从该 source 读取实际 `view_token`，不反向用 `view_token` 猜合集。
- `GET session`、笔记新增/修改/删除、AI 提问、Markdown 导出、重新解析和签发媒体凭证都先执行同一判定。
- 媒体文件端点不接收长期 Bearer 头，改为校验上一节定义的短时签名凭证。
- 越权与不存在统一返回 404；认证缺失或无效仍按当前项目规则返回 401。

对应 API 分为两组，前端根据当前路由选择，不把合集退化为单篇调用：

- 单篇沿用 `/api/study/{view_token}`、`/{view_token}/notes`、`/{view_token}/ai-chat` 和 `/{view_token}/export/markdown`。
- 合集新增 `/api/study/collections/{collection_id}/sources/{source_id}`，并在其下提供 `notes`、`ai-chat`、`export/markdown` 和 `source-file`；服务端从 source 解析真实 `view_token`。

Study 笔记必须同步补齐归属和上下文，避免同一 `view_token` 被不同用户或多个合集复用时串数据：

- `study_notes` 增加 `owner_user_id`、可空 `collection_id` 和可空 `source_id`。
- 单篇按 `owner_user_id + view_token` 读取；合集按 `owner_user_id + collection_id + source_id` 读取。
- 单用户回退模式把无 owner 的旧笔记归给 `legacy_user`；多用户模式下无法证明归属的旧笔记保留但不展示。
- AI 提问不新增跨会话持久化；Markdown 导出只包含当前归属、当前上下文的笔记。

现有 `/view/{view_token}` 保持原行为；上述收紧只作用于 Study 播放器和合集数据接口，不把播放器改造扩大成全站认证重构。

### 5.5 前端状态控制器

内容选择、临时本地播放、上传状态、服务端会话和合集导航由一个页面状态控制器协调，但拆分为独立职责：

- `library-controller`：搜索、分页、单篇和合集列表。
- `local-media-controller`：`File` / `FileList`、对象 URL 生命周期和上传前播放。
- `study-session-controller`：`view_token`、轮询、字幕、AI 和失败状态。
- `collection-playback-controller`：选集、上一集、下一集和每集进度。

控制器之间只交换普通数据对象，不互相直接操作内部状态。

## 6. 关键数据流

### 6.1 选择已解析单篇

1. `/study` 请求 `/api/study/library`。
2. 用户点击内容卡片。
3. 页面进入播放器状态，并带 Bearer 认证加载 `/api/study/{view_token}`。
4. 媒体从 session 返回的短时签名 `media_url` 加载。
5. 逐字稿、AI 解读和播放进度同步渲染。

### 6.2 选择新的本地单篇

1. 浏览器文件选择器返回 `File`。
2. 前端立即创建对象 URL，在当前页面进入播放器并开始播放。
3. 后台调用现有 `POST /api/study/upload`。
4. 上传响应返回 `view_token` 后，播放器绑定服务端 Study 会话，并使用 `history.replaceState` 更新为 `/study/{view_token}`，不重新加载正在播放的页面。
5. 页面轮询 Study 会话，逐步显示上传、转录、AI 和字幕状态。
6. 服务端源文件可用后，从已认证的 session 响应取得短时签名 `media_url`，释放临时对象 URL 并切换媒体地址。

### 6.3 选择已有合集

1. `/study` 读取真实合集列表。
2. 用户选择合集后，默认打开浏览器记录的上次播放分集；没有记录时打开第一集。
3. 跳转或替换为 `/study/collections/{collection_id}/sources/{source_id}`；服务端从该 source 取得实际 `view_token` 并加载统一播放器。
4. 选集下拉列表显示全部分集及其真实状态。
5. 切换分集只替换当前媒体和 Study 会话，不停止其他分集的后台处理。

### 6.4 创建新的本地合集

1. 用户选择文件夹或多个音视频。
2. 前端按文件名自然排序，立即使用第一集的对象 URL 进入播放器。
3. 合集标题默认使用文件夹名称；多文件选择没有文件夹名称时使用第一个文件名的公共前缀或“本地音视频合集”。创建人默认“未归属”，以后可在系列深度学习页面修改。现有 `video_course` 类型继续作为音视频合集容器，MP3/M4A/WAV 等音频扩展名与视频扩展名一样被接受；播放器再按 MIME 类型渲染 `<audio>` 或 `<video>`。
4. 前端调用现有合集创建和批量上传接口。
5. 上传成功后，用服务端返回的 source 顺序替换临时选集数据，并绑定每集 `view_token`。
6. 获得正式 `collection_id/source_id` 后，地址替换为合集播放器路由；下拉列表持续显示每集上传、排队、转录、成功或失败状态，用户可播放任何仍有本地 `File` 对象的分集。

## 7. 播放器状态

### 7.1 临时本地播放

- 媒体立即可播。
- 顶部显示上传进度。
- 字幕区显示“正在上传，上传后开始转录”。
- AI 区保持折叠并显示不可用原因。

### 7.2 解析中

- 媒体继续播放。
- 字幕区显示真实阶段和百分比。
- 已产生的字幕段落可以追加显示；没有增量字幕时保持状态提示，不伪造内容。
- AI 区显示“逐字稿完成后生成”。

### 7.3 已完成

- 当前字幕条跟随媒体时间轴。
- 右侧逐字稿自动跟随并高亮当前段。
- 点击逐字稿跳转到对应时间。
- AI 解读和提问按需打开。

### 7.4 上传或解析失败

- 只要浏览器仍持有本地 `File`，媒体继续可播。
- 状态区域显示服务端返回的真实失败原因。
- 上传请求失败且浏览器仍持有本地 `File` 时显示“重新上传”，继续沿用当前对象 URL。
- 服务端已接收但解析失败时显示“重新解析”：单篇调用新增的 `POST /api/study/{view_token}/retry`，合集调用现有 source retry 接口。
- 单篇重新解析仅在当前用户拥有旧任务、旧任务已终止且安全源文件仍存在时允许。服务端以同一源文件创建新的 `task_id/view_token`，写入新的审计归属并返回新 token；前端用 `history.replaceState` 切换到新地址并把本地播放进度迁移到新键。旧任务和旧笔记保留为历史，不自动复制到新会话。
- 源文件已丢失时不显示“重新解析”，改为提示重新选择本地文件。
- 失败分集不影响合集其他分集。

## 8. 播放进度

第一版使用 `localStorage` 保存，不新增数据库字段：

- 单篇键：`view_token`。
- 合集键：`collection_id + source_id`。
- 记录当前时间、媒体总时长和更新时间。
- 最多每 5 秒写入一次，并在暂停、切集和离开页面时补写。
- 内容选择页用该数据显示“继续播放”；没有进度时显示“从头播放”。

临时本地内容在获得 `view_token` 前使用页面内临时 ID；上传成功后迁移到正式键。

### 8.1 拖动定位

- 复用原生范围输入作为进度条，支持鼠标、触控和键盘操作。
- 拖动过程中只预览目标时间和对应字幕，不让媒体自身的 `timeupdate` 把滑块位置覆盖。
- 松手或键盘完成调整后，把媒体定位到目标时间并立即播放。
- 媒体时长尚不可用时不执行定位，也不伪造可播放进度。

## 9. 刷新与生命周期

- 上传完成前刷新或关闭页面会失去浏览器 `File` 和对象 URL，页面必须显示“上传完成前请保持页面打开”。
- 上传完成后刷新单篇或合集正式地址可以从服务端恢复。
- 切换内容或释放页面时调用 `URL.revokeObjectURL`，避免长音视频造成内存泄漏。
- 合集批量上传仍在进行时，不能因为切集而取消上传请求。

## 10. 明确不做

- 不替换或删除 `/view/{view_token}`。
- 不改变现有转录和 AI 生成算法。
- 不新增跨设备播放进度同步。
- 不做通用媒体资料库、标签系统、播放列表编辑器或收藏夹。
- 不支持播放源文件已丢失的历史记录。
- 不为在线平台页面尝试抓取浏览器不可直接播放的媒体流。
- 不在第一版实现断点续传或关闭页面后的浏览器后台上传。

## 11. 错误与空状态

- 没有可播放历史：显示本地文件选择入口，不显示虚构示例卡片。
- 没有合集：显示创建本地合集入口。
- API Key 缺失：使用当前项目统一提示，引导到设置页。
- 源文件在列表加载后被清理：进入播放器时返回明确不可用状态，并从下一次列表刷新中移除。
- 合集某一集缺失：该集从可播放项中隐藏或置为不可选择，但合集其他集正常显示。
- 搜索无结果：保留本地导入入口。

## 12. 兼容性与迁移

- 共享侧栏入口从静态预览地址改为 `/study`。
- 单篇上下文入口改为真实 `/study/{view_token}`，合集上下文入口改为带 `collection_id/source_id` 的正式地址。
- 当前 `study.html`、`study.js` 和 `StudyService` 作为现有可运行基础逐步升级，不新建第二套真实播放器。
- 预览页的视觉结构迁移完成后，移除正式导航对预览页的引用，并删除或明确隔离预览专用资源，避免再次被误认为线上功能。
- 现有缓存、Study 笔记、合集、转录和 AI 数据继续复用。

## 13. 测试与验收

### 13.1 后端测试

- Study 内容库只返回当前 API Key 可归属的任务。
- 没有源文件或非音视频内容不进入内容库。
- Study 上传写入审计归属。
- 单篇、合集的 session、笔记、AI、导出、重试和媒体签发都执行统一归属校验。
- 单用户模式正确认领旧合集；多用户模式不暴露 owner 不明的旧合集。
- 统一源文件解析只允许配置目录内的文件。
- 单篇、Study 上传和合集 source 均能通过短时签名媒体地址播放并支持 Range 请求。
- 过期、篡改或跨内容复用的媒体凭证被拒绝，URL 中不包含长期 API Key。
- 缺失文件返回稳定的不可用错误，不泄露磁盘路径。

### 13.2 前端行为测试

- `/study` 显示真实单篇和合集数据，不含示例内容。
- 选择本地音频或视频后，在上传响应前即可播放。
- 上传成功后页面无刷新绑定 `view_token`。
- 解析中、已完成和失败状态正确切换。
- 合集选集下拉能任意切换，单篇不显示合集控件。
- 同一个 `view_token` 同时出现在多个合集时，播放器始终按 URL 中的 `collection_id/source_id` 显示正确上下文。
- 当前字幕、逐字稿点击跳转和 AI 按需打开正常工作。
- 对象 URL 在内容切换和页面退出时释放。
- 播放进度按内容隔离并能恢复。

### 13.3 回归测试

- `/add_task_by_web` 原有上传、链接解析和历史卡片行为不变。
- `/collections` 的创建、追加、重试、全系列解读和源详情行为不变。
- `/view/{view_token}`、导出、图解生成和现有 Study API 不回归。
- 桌面和 390px 窄屏无横向溢出。

### 13.4 验收标准

1. 用户从 `8000` 服务的侧栏进入 `/study`，不需要输入隐藏 URL 或访问独立端口。
2. 文件选择按钮会打开真实系统文件选择器。
3. 单篇和合集列表来自真实数据；没有数据时为空状态，不显示示例。
4. 新本地单篇和合集第一集可以立即播放。
5. 上传和解析状态来自真实接口，完成后字幕和 AI 自动可用。
6. 已有合集可通过下拉列表任意切换分集。
7. 源文件不可用的历史记录不会出现在选择器中。
8. 现有单篇和合集功能通过回归验证。
