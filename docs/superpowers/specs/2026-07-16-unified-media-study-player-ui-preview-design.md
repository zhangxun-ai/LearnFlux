# 统一音视频学习播放器 UI 预览设计

## 目标

在不影响现有单篇解读、合集、转录和 Study 逻辑的前提下，把已确认的播放器 UI 放进当前项目，并从现有工作台提供自然入口，供用户在真实使用路径中评审。

## 本轮范围

- 新增独立静态预览页，不替换任何现有页面。
- 在共享侧栏增加稳定的“边播边学”入口。
- 在已完成的单篇音视频记录中增加“边播边学”上下文入口。
- 在合集已完成的音视频源详情中增加“边播边学”上下文入口。
- 使用当前项目的应用侧栏、顶部栏、主题变量和视觉语言。
- 展示播放器、画面下方固定字幕、右侧同步逐字稿和按需 AI 入口。
- 提供四种纯前端预览状态：单个视频、单个音频、合集视频、合集音频。
- 合集状态显示紧凑选集下拉框；单文件状态完全隐藏合集控件。
- 页面明确标记为 UI 预览，所有内容均为示例，不接真实接口。

## 明确不做

- 不修改 `/view/{view_token}`、`/study/{view_token}` 的既有功能。
- 不修改上传、转录、缓存、AI 生成、源文件解析或合集导航逻辑。
- 不新增数据库字段、API 或依赖。
- 不实现真实播放、字幕时间同步、选集切换、AI 抽屉数据加载或播放进度保存。

## 入口设计

1. **稳定入口**：共享侧栏“核心工具”中增加“边播边学”，默认打开单个视频预览。
2. **单篇上下文入口**：仅已完成且拥有 `view_token` 的音视频历史卡片显示“边播边学”；文件、帖子、处理中和失败记录不显示。
3. **合集上下文入口**：仅合集内已完成且拥有 `view_token` 的音视频源显示“边播边学”；文档、处理中和失败源不显示。
4. **预览状态传递**：入口通过 `?state=` 选择单篇或合集预览状态，仍不读取真实任务数据。

## 页面结构

1. 应用侧栏和顶部栏：复用现有项目视觉结构。
2. 预览控制条：仅用于切换四种 UI 状态。
3. 内容标题区：显示内容类型、标题和按需操作。
4. 合集上下文：仅合集状态显示选集下拉框。
5. 媒体区：视频使用课程画面示意；音频使用封面和波形示意。
6. 固定字幕条：位于媒体画面下方，不遮挡视频。
7. 同步逐字稿：右侧常驻，当前段高亮。
8. AI 入口：保持折叠，只展示“问当前字幕”和“打开 AI 解读”。

## 文件边界

- `src/web/static/study-player-preview.html`：预览页语义结构。
- `src/web/static/css/study-player-preview.css`：仅预览页加载的样式。
- `src/web/static/js/study-player-preview.js`：四种展示状态切换，不访问接口。
- `src/web/static/js/app-shell.js`：向现有应用侧栏注入稳定入口。
- `src/web/static/index.html`：让首页按资源版本加载共享侧栏脚本，避免入口被旧缓存遮蔽。
- `src/web/static/js/app.js`：为符合条件的单篇音视频历史卡片渲染上下文入口。
- `src/web/static/collections.html`：在合集源操作区放置入口元素，并按资源版本加载共享侧栏脚本。
- `src/web/static/js/collections.js`：根据合集源状态控制入口显隐。
- `tests/unit/test_study_player_preview_assets.py`：验证预览资源、隔离边界和四种状态入口。

## 成功标准

- 用户可以从现有侧栏进入预览，不需要手动输入 URL。
- 用户可以从已完成的单篇音视频或合集音视频源就地进入对应预览状态。
- 四种预览状态均可切换，单文件状态不显示合集控件。
- 桌面宽屏下媒体、固定字幕与逐字稿同时可见。
- 窄屏下布局能纵向堆叠，无明显横向溢出。
- 既有页面功能、API 和路由不变；只新增预览入口所需的最小前端改动。
