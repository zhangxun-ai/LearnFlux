# Codex 工作流简化设计

## 目标

把 Codex 的日常使用收敛到少数稳定规则：一个任务对应一个交付物，开工时明确执行边界，非平凡改动使用隔离工作区，项目只保留一套有效验证命令。

## 设计

1. 全局 `~/.codex/AGENTS.md` 增加最小任务合同、范围切换、在制品限制和默认工具路由。缺失信息由代理根据上下文推断，只有高风险歧义才询问用户。
2. `VideoTranscriptAPI` 以 `uv`、`pyproject.toml` 和 pytest 为唯一开发与测试事实来源。快速验证只跑目标或单元测试；完整验证运行默认离线套件。features、integration、llm、manual、performance 和 platforms 测试必须按文件显式运行，避免误触真实服务、凭据、网络和数据写入。
3. 删除已失效的 `scripts/run_tests.py`，同步更新项目说明、测试说明和 README；不增加任务运行器或新依赖。
4. 当前任务改为短标题并保留在隔离 worktree。旧任务只在能可靠判断为长期未更新且已完成时归档；证据不足时不批量改变状态。

## 非目标

- 不修改业务代码、数据库、生产配置或密钥。
- 不自动提交、推送或部署。
- 不批量删除任务或技能。
- 不为其他项目猜测验证命令；本轮只建立全局规则并修正当前项目。

## 验证

- 为项目文档和命令契约增加一个轻量测试，先证明旧命令会失败，再更新文档使其通过。
- 先用 `pytest --collect-only` 负向检查确认不会收集任何 opt-in 测试目录，再运行快速验证和默认离线完整验证。
- 用文本检查确认全局规则包含任务合同、范围切换、在制品限制和工具路由。
- 检查最终 diff，确保没有业务源码变化。
