# Obsidian 文字稿可读分段设计

## 背景

当前 Obsidian 文字稿将每个 ASR 片段渲染成独立行，并在每行前添加时间戳。短片段密集时，页面更像调试数据而不是文章，不利于连续阅读，也会让 AI 获得过度碎片化的上下文。

## 目标

- 将相邻 ASR 片段确定性地合并为可连续阅读的自然段。
- 每个自然段只保留一个段首时间戳，兼顾回看定位。
- 保持原始文字顺序和内容，不调用 LLM，不做总结、删减或语义改写。
- 保持输出结构稳定，方便 Markdown 阅读器和 AI 按段处理。
- 再次同步时更新系统管理的文字稿，不改变用户笔记文件。

## 非目标

- 不生成语义章节标题或 AI 摘要。
- 不修改网页逐字稿的展示和跳转粒度。
- 不改变转录、时间轴、Vault 绑定或笔记冲突处理。
- 不迁移或批量扫描 Vault；已有文字稿在用户再次同步对应课程时更新。

## 输出格式

保留现有 YAML frontmatter 和一级标题，并新增固定的正文标题：

```markdown
# 第01课：核心概念

## 文字稿

**00:00** 用逻辑驱逐混乱，用秩序重塑人生，超级思考术是一种可以学习的方法……

**01:18** 接下来介绍生活、工作和学习中常用的思维模型……
```

有可定位片段时，段首使用 `**MM:SS**` 或 `**HH:MM:SS**`。整段均无有效时间时不输出时间戳。段落之间保留一个空行，不使用表格、列表或逐句标题。

## 确定性分段规则

按原始顺序处理非空片段，并做以下最小规范化：

1. 去除片段首尾空白，不改变片段内部文字。长度均按去除空白后的 Unicode 字符数计算。
2. “连接标点”固定为 `，,、；;：:。.！？!?…`，“句末标点”固定为 `。.！？!?…`；标点后允许跟随 `”’）》】」』` 这些闭合符号。前一片段以连接标点结束，或后一片段以连接标点开始时直接连接，否则在两者之间插入中文逗号。
3. 结束自然段时：已有句末标点则保持不变；末尾是逗号、顿号、分号或冒号时将该连接标点替换为中文句号（闭合符号保留在句号之后）；其他情况追加中文句号。
4. 每段时间戳取该段第一个可定位片段的开始时间。

对每个片段严格按以下顺序判断，完整片段永不截断：

1. **超长片段隔离**：当前片段自身超过 320 字时，先结束任何已有段落（不受 80 字最小条件限制），再将该片段完整写成独立段落并立即结束；随后处理下一片段。
2. **静音边界（加入前）**：只有同时具备上一片段 `end_seconds` 和当前片段 `start_seconds`，且差值至少 8 秒时才算可靠静音。当前段不少于 80 字时，先结束当前段，再用当前片段开始新段。
3. **硬上限（加入前）**：计算加入分隔符和当前完整片段后的预计长度；若预计超过 320 字且当前段不少于 80 字，先结束当前段，再加入当前片段。
4. **加入片段**：按上述连接标点规则追加当前片段，并在本段尚无时间戳时记录当前片段的有效开始时间。
5. **目标上限（加入后）**：累计达到 260 字时立即结束当前段。
6. **自然句尾（加入后）**：未达到 260 字，但累计不少于 180 字且当前片段以句末标点结束时，结束当前段。
7. **输入结束**：结束剩余非空段落。

因此优先级固定为：超长片段隔离 → 静音边界 → 加入前硬上限 → 加入完整片段 → 260 字目标上限 → 180 字后的自然句尾。段落通常为 180–260 字；只有片段边界限制、80 字最小提前分段条件或单个超长片段会使长度落在范围外。

这些规则只改善标点和段落边界，不重排片段，不修正文案，也不推断说话人或主题。

## 同步行为

文字稿仍是应用完全管理的文件。新的渲染结果参与现有 managed hash：

- 首次同步创建新格式文字稿。
- 旧格式文字稿再次同步时原位更新为新格式。
- 内容未变化且已是新格式时保持 `unchanged`。
- 笔记文件和用户自定义笔记 frontmatter 不受影响。
- 写入失败仍沿用现有部分成功与重试机制。

## 验证

- 单元测试覆盖短碎片合并、段首时间戳、中英文标点衔接、自然边界、静音边界、320 字上限、短段后超长片段隔离、小时级时间戳和无时间戳回退。
- 同步测试覆盖旧文字稿被更新、新格式重复同步保持幂等、笔记文件不变。
- 运行 Obsidian/学习页相关测试、JavaScript 语法检查和完整单元测试。
