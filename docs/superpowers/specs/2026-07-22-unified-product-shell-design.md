# LearnFlux 统一产品壳层与生产页面视觉设计

## 1. 决策摘要

本设计在不改变现有业务流程、路由、后端 API 和页面 JavaScript 业务数据契约的前提下，统一 LearnFlux 生产页面的应用壳层、侧边导航、色彩、排版、组件状态和响应式行为。

已确认的产品决策：

- 采用 A+ 侧边栏：桌面端为 `280px 展开态 / 72px 图标栏态`，移动端为关闭/抽屉态。
- 分类可以独立折叠；图标栏始终展示全部入口，不受分类折叠状态影响。
- 采用品牌冷色产品系统：蓝青 Logo 对应的蓝色为主强调色，冷灰建立页面层次，青色只用于信息与数据，珊瑚色只用于提醒。
- 所有页面共享同一应用壳层和组件词汇；页面差异只能发生在主内容结构和信息密度中。
- 基础 HTML 保留完整可用的导航与 SVG 图标；JavaScript 只增强状态，不重建导航 DOM。
- 每个可选功能都有稳定的 feature ID；开发者通过项目内前端配置的 `true / false` 控制侧边栏、首页卡片和快捷入口是否展示。
- 品牌资产保持现状：继续使用现有 LearnFlux 蓝青 Logo、字标、favicon 与 App Icon，不重新绘制、不换字标、不改变图形比例。

## 2. 目标与验收标准

### 2.1 目标

- 用户在任意生产页面间切换时，侧边栏的底色、宽度、字号、行高、图标、分组、选中态和行为保持一致。
- 页面背景、侧栏、卡片、控件和语义状态使用同一套设计 token，消除拼接感。
- 桌面端可释放内容空间，移动端始终有清晰且可触达的导航入口。
- 页面 CSS 无权修改共享壳层；共享视觉调整可以改一处全站生效。
- 保留现有页面 DOM ID、表单、API 调用、事件绑定和业务功能。
- 未准备好的模块可以在发布前通过一处代码配置退出产品界面，重新启用时只改同一布尔配置；不改后端 API 逻辑。

### 2.2 可验证的完成条件

- 所有生产路由的 `.sidebar`、`.brand-link`、`.nav-group-title`、`.nav-item`、`.nav-item.is-active` 在同一主题和断点下具有相同的计算样式。
- 桌面展开态宽度为 280px，图标栏态宽度为 72px；导航项可点击区域至少 44×44px。
- JavaScript 正常时，900px 以下所有页面都显示统一的 44×44px 菜单按钮，侧栏作为抽屉打开；`Esc` 和遮罩可以关闭。JavaScript 禁用时，不可关闭的核心导航以普通文档流显示。
- 心流阅读移动端不再隐藏唯一导航入口；心流写作不再首次访问时擅自折叠侧栏。
- 趋势雷达等页面的通用元素规则不会影响共享导航。
- JavaScript 禁用时，核心导航仍包含分类、链接、SVG 图标和正确的服务端/静态 active 回退；依赖代码配置的可选入口保持 fail-closed 隐藏。
- 明暗主题正文、次要文字、占位文字和主要按钮达到 WCAG AA 对比度。
- 新增跨路由浏览器契约覆盖桌面、移动端、明暗主题、展开/图标栏、分类折叠和键盘操作。
- 将 `trend_radar` 等功能设置为 `false` 后，其侧栏项、首页卡片、快捷入口和关联链接在所有生产页面中均不展示；设置为 `true` 后随前端资源刷新恢复。
- 功能开关只控制 UI 发现性，不是权限或安全边界；直接 URL 与后端 API 保持原有行为。
- 功能配置缺失、键名错误或值不是布尔值时测试失败；运行时安全回退为隐藏该可选入口，不能散落默认值。

## 3. 当前问题与根因

### 3.1 多个视觉来源竞争

当前侧栏样式同时存在于：

- `src/web/static/css/app-shell.css`
- `src/web/static/css/product-linear.css`
- `src/web/static/css/home-linear.css`
- `src/web/static/css/product-linear-core.css` 的页面特例
- 各功能页面 CSS 中未限定作用域的规则

`editorial.css` 声称是唯一设计系统，但 `product-linear.css` 和 `home-linear.css` 会重写其主要 token。最终效果依赖页面加载顺序，而不是稳定组件契约。

### 3.2 页面样式泄漏到壳层

- `trend-radar.css` 对裸 `a/button/input/select` 设置 `min-height: 44px`，把该页导航项从 40px 撑到 44px。
- 共享导航没有显式 `line-height`，会继承页面 `body` 的 `normal` 或 `1.6`，形成约 17px 与 23.04px 的排版差异。
- `product-linear-core.css` 单独改变心流写作的侧栏和顶栏背景。

### 3.3 行为和结构不是单一来源

- 侧栏 HTML 复制在 9 个静态页面、`base.html` 和 `flywheel.html` 中。
- `app-shell.js` 又维护一份 `NAV_GROUPS`，加载后删除 HTML 导航并改用 Unicode 字符重建。
- 结果是一次加载内先显示 SVG 导航，再切换为另一套图标；脚本失败或版本漂移时会得到不同结构。

### 3.4 响应式入口不完整

心流阅读在移动端把顶栏强制隐藏，而打开侧栏的按钮位于该顶栏中。侧栏同时位于屏幕外，因此用户没有导航入口。

## 4. 设计原则如何落地

### 4.1 层次、对齐与留白

- 壳层采用固定网格：280px 展开侧栏、72px 图标栏、主内容自适应。
- 侧栏项目、分类标题、品牌区和控制按钮使用固定高度、内边距和对齐线。
- 通过 8px 基础间距与分组留白表达分类，不使用装饰性分割线堆叠。
- 主要动作只允许一种主按钮样式；次要动作降低色彩和权重。

### 4.2 一致性与渐进披露

- 分类默认展示核心入口，用户可独立折叠非必要分类。
- 分类折叠不会改变图标栏内容；图标栏始终保留所有入口，避免用户回忆隐藏项目。
- 页面高级选项放入现有 `details`、抽屉或内联展开区，不用新的模态框替代简单展开。

### 4.3 反馈与用户可控

- 整栏切换、分类折叠、移动抽屉都有即时视觉状态和 ARIA 状态。
- 用户手动选择优先于页面默认；任何业务页面都不能覆盖用户侧栏偏好。
- 动画只表达状态，时长 180ms，使用 ease-out；`prefers-reduced-motion` 下立即完成。

### 4.4 无障碍

- 所有导航链接和控制目标至少 44×44px。
- 分类标题使用真实 `button`，支持 Enter/Space，设置 `aria-expanded` 和 `aria-controls`。
- 抽屉打开后焦点进入当前导航项，关闭后回到触发按钮；隐藏内容不进入 Tab 顺序。
- 图标栏链接保留可访问名称；视觉工具提示在 hover 和 `focus-visible` 时出现。
- 当前页面同时使用图标/形状、文字或边框表达，不只依赖颜色。

### 5.2 使用规则

- 侧栏与页面使用相邻中性色层级，不能使用不同色相的独立主题。
- 主强调色只用于主要操作、当前导航、焦点和选中状态，面积不超过常规产品页面的约 10%。
- 青色用于图表与信息语义，珊瑚只用于提醒或品牌微标，不用于普通主按钮。
- 业务页面不得定义新的页面背景、主文字色或主强调色。
- 数据可视化可以使用受控调色板，但图表颜色不得反向污染按钮或导航。
- 亮色语义浅底/文字配对固定为：info `#E7F7FA/#0F7890`（4.64:1）、success `#E9F8F0/#18794E`（4.93:1）、warning `#FFF4D8/#8A5B00`（5.36:1）、danger `#FDECEA/#B42318`（5.75:1）、attention `#FCEDEA/#B93C35`（4.90:1）。
- 暗色语义浅底/文字配对固定为：info `#18333C/#5DD5E8`（7.70:1）、success `#19372C/#55D69E`（7.08:1）、warning `#3A301E/#F0C66C`（8.02:1）、danger `#3D2527/#FF8A80`（6.16:1）、attention `#402629/#FF948C`（6.46:1）。

### 5.3 现有品牌资产使用规则

- 继续复用 `src/web/static/icon/learnflux-logo.png`、`learnflux-favicon-32.png`、`learnflux-icon-256.png`、`learnflux-apple-touch-icon.png` 和现有 manifest 引用；不生成替代素材。
- 展开侧栏显示完整 Logo/字标，图标栏显示现有图形标；只通过容器尺寸和 `object-fit: contain` 缩放，不裁切或重排图形。
- Logo 使用透明或品牌冷灰承载面，保留至少一个图标笔画宽度的安全留白；暗色模式不反相、不换色，必要时只调整承载面的对比。

## 6. A+ 侧边栏交互规格

### 6.1 桌面展开态

- 宽度 280px；品牌区、主题按钮和整栏切换按钮位于同一对齐行。
- 导航项高度与最小触控区域均为 44px，字号 14px，行高 20px。
- 分类标题为 36px 高按钮，字号 12px，行高 16px。
- 当前项目使用白色 surface、结构边框、轻微 2px 以内阴影和主蓝图标/焦点；不使用彩色侧边条。

### 6.2 分类折叠

- 分类独立折叠，不采用“只能打开一组”的强制手风琴。
- 分类状态使用单独的持久化对象保存。
- 导航进入某页面时，仅当所属分类没有显式用户保存值时自动展开，以保证系统状态可见；不得覆盖用户明确保存的 `false`。
- 用户可以折叠当前分类；分类标题显示主蓝状态圆点，表明当前页面位于该分类。
- 折叠动画只改变内容的可见性和必要的尺寸，不让隐藏链接保留焦点。

### 6.3 图标栏态

- 宽度 72px；由用户主动切换，所有页面共享并持久化该状态。
- 图标栏展示全部导航入口，按分类使用间距分组，不应用展开态的分类折叠结果。
- 每个链接保持 44×44px；SVG 图标统一为 18×18px。
- hover 与 `focus-visible` 显示文字工具提示；工具提示不被滚动容器裁剪。

### 6.4 移动端

- 900px 以下不使用图标栏，侧栏默认为关闭的抽屉。
- 每个页面都显示同一 44×44px 菜单按钮；禁止页面把该入口隐藏。
- 抽屉宽度 `min(86vw, 320px)`，带遮罩；点击链接、遮罩或按 Esc 关闭。
- 抽屉打开时阻止背景滚动并管理焦点；关闭后恢复触发按钮焦点。
- 离屏抽屉规则只在壳层脚本成功初始化并给 `<html>` 添加 `shell-enhanced` 后生效；无 JavaScript 时侧栏保持在页面顶部的普通文档流中，分类默认展开，核心链接可直接访问，可选入口保持隐藏。

### 6.5 状态持久化

建议数据结构：

```json
{
  "mode": "expanded",
  "groups": {
    "core": true,
    "flow": false,
    "insight": true,
    "system": true
  }
}
```

- 继续兼容现有 `vta_app_shell_sidebar` 的 `expanded/collapsed` 字符串，并在首次读取时迁移为新结构。
- 无有效保存值时桌面默认展开；不再根据 `focus-body` 设置特殊默认。
- 移动抽屉的开关状态不持久化。

## 7. 共享结构和职责边界

### 7.1 单一导航数据

导航定义只允许存在一份，包含：

- 分类 ID、标签与排序。
- 路由、别名、SVG 图标标识、可访问名称。
- 当前路径匹配规则。

生产 HTML 在服务端模板或仓库内静态同步阶段得到完整导航，不由客户端重新创建。对于当前混合的 Jinja、内联首页和静态 HTML：

- Jinja 页面由共享 partial/macro 输出侧栏。
- 静态页面和 `views.py` 的内联首页通过仓库内确定性同步脚本更新同一共享导航片段，并以契约测试保证输出一致；不改变它们当前的路由服务方式。
- `app-shell.js` 只读取现有 DOM、设置 active 回退、增强折叠/抽屉/主题行为，不调用 `replaceChildren` 重建导航。

### 7.2 UI 功能展示配置

功能开关是代码内的前端展示配置，不进入 `config/config.jsonc`、数据库、设置页、权限系统或任何后端 API。单一来源为 `src/web/static/js/ui-features.js`，使用可审查的布尔常量：

```js
window.LEARNFLUX_UI_FEATURES = Object.freeze({
  collections: true,
  visual_learning: true,
  study_player: true,
  reading: true,
  focus_studio: true,
  post_insight: true,
  trend_radar: false,
  flywheel: true,
  history: true,
});
```

首轮可配置项：

| Feature ID | 默认 | UI 入口 |
|---|---:|---|
| `collections` | `true` | 系列深度学习导航、首页卡片与快捷入口 |
| `visual_learning` | `true` | 图解生成导航、首页卡片与快捷入口 |
| `study_player` | `true` | 边播边学导航、首页卡片与快捷入口 |
| `reading` | `true` | 心流阅读导航、首页卡片与快捷入口 |
| `focus_studio` | `true` | 心流写作导航、首页卡片与快捷入口 |
| `post_insight` | `true` | 帖子洞察导航、首页卡片与快捷入口 |
| `trend_radar` | `false` | 趋势雷达导航、首页卡片与快捷入口 |
| `flywheel` | `true` | IP 对标导航、首页卡片与快捷入口 |
| `history` | `true` | 历史记录导航、首页卡片与快捷入口 |

`/`、`/add_task_by_web` 和 `/settings` 是不可关闭的产品骨架，不出现在配置中。

行为契约：

- 所有可选 UI 入口使用 `data-feature="<feature_id>"` 标记，并在基础 HTML 中带 `hidden`，避免 `false` 项在脚本执行前闪现。
- `ui-features.js` 必须先于 `app-shell.js` 加载；壳层脚本只对值严格等于 `true` 的入口移除 `hidden`，`false`、缺失键或非法值都保持隐藏。
- `app-shell.js` 提供唯一的 feature 可见性处理器：初始化时扫描现有 `[data-feature]`，随后用一个作用于应用内容根节点的 `MutationObserver` 处理动态插入的入口。观察器只检查新增节点及其带标记的后代，不监听属性变化，也不对整棵 DOM 重复扫描。
- 业务脚本动态创建跨功能入口时必须同时写入 `data-feature` 和 `hidden`，但不得直接读取 `LEARNFLUX_UI_FEATURES`；这样新增入口在进入 DOM 后由共享处理器统一决定是否展示。
- 展开侧栏、72px 图标栏、移动抽屉、首页卡片、空状态 CTA 和页面内快捷入口使用同一 feature ID，禁止分别维护隐藏名单。
- 配置只影响入口展示。直接访问功能 URL、浏览器书签、页面业务脚本和全部后端 API 保持原样；该机制不能替代鉴权、授权或服务端发布门禁。
- 开关不写入 localStorage，不提供设置页 UI，不支持运行时远程切换。修改 `true / false` 后随静态资源刷新或下一次前端发布生效。
- 首轮不引入用户分群、灰度、定时开关、功能依赖图或第三方 feature flag 服务。

### 7.3 CSS 所有权

- `editorial.css`：只保留兼容 token 或被新的产品 token 文件替代，不再声明应用壳层结构。
- `app-shell.css`：唯一拥有 `.sidebar`、`.topbar`、`.nav-*`、`.brand-*`、`.shell-*`。
- `product-linear.css`：收敛为全局产品 token 和共享基础组件，不再重写壳层尺寸与排版。
- `home-linear.css`：只负责首页主内容，不得包含侧栏选择器。
- `product-linear-{core,insights,system}.css`：仅适配主内容区；选择器必须以页面类和页面内容根节点开头。
- 功能 CSS：禁止裸 `:root`、`body`、`a`、`button`、`input`、`select` 或共享壳层选择器。

### 7.4 资源版本

- 所有共享 CSS/JS 使用同一套基于文件修改时间或内容哈希的版本生成方式。
- 删除 `20260712`、`20260722-blue`、手写整数和无版本参数并存的情况。
- `ui-features.js` 使用同一版本策略；service worker 更新 cache name 和该资源的预缓存版本，避免客户端继续使用旧展示配置。

## 8. 生产页面原型与迁移

### 8.1 单任务工作台

页面：单篇深度学习、设置和导入型入口。

- 使用清晰页面标题、简短说明和一个主要任务区域。
- 主要操作在视觉层级中唯一突出；高级选项渐进披露。
- 页面不使用大面积品牌色或独立背景主题。

### 8.2 资料库与列表

页面：系列深度学习、心流阅读、历史记录。

- 统一页面头部、搜索/筛选工具栏、列表行、空状态和分页。
- 相关操作通过距离分组，避免每块都套独立卡片。
- 行项目使用同一选中、悬停、加载和批量操作反馈。

### 8.3 双栏沉浸工作区

页面：边播边学、图解生成、心流写作。

- 允许媒体/控制区与内容区使用不同列宽，但外层页面背景和控件语言一致。
- 心流写作的氛围背景只属于编辑画布，不改变共享侧栏。
- 沉浸模式可以隐藏非必要页面工具，但不能擅自改变用户侧栏偏好。

### 8.4 分析仪表盘

页面：帖子洞察、趋势雷达、IP 对标。

- 保持较高信息密度，但统一标题、指标、筛选、表格、图表容器和语义状态。
- 页面可以使用受控数据可视化颜色，不能修改全局强调色和侧栏。
- 禁止裸元素选择器；所有规则限定在业务页面内容根节点内。

### 8.5 结果与阅读内容

转录结果、清洗结果、处理中和错误页面继续复用 `base.html` 壳层。

- 内容正文可以使用更宽松的阅读排版，但外层页面背景、标题区、按钮和状态组件保持统一。
- 加载、错误、空和成功状态复用全局状态组件，而不是各模板单独定义颜色。

## 9. 组件与状态词汇

共享组件至少包含：

- 按钮：primary、secondary、ghost、danger；每种包含 default、hover、focus、active、disabled、loading。
- 表单：input、textarea、select、checkbox、radio；包含 label、help、error、disabled。
- 页面头部、工具栏、列表行、分页、标签和状态徽标。
- 空状态、骨架加载、内联错误和重试区。
- 抽屉、工具提示和必要的对话框。

状态原则：

- 加载：内容区域使用骨架，不在整页中央只放旋转图标。
- 空状态：说明原因并提供一个明确下一步。
- 错误：说明发生了什么、保留用户输入、提供重试或返回。
- 成功：操作附近即时反馈；只有跨页面重要事件使用 toast。

## 10. 响应式与排版

- 断点以结构变化为依据，壳层统一使用 900px；页面可以在内容区增加必要断点。
- 产品 UI 使用固定 rem 排版阶梯，不使用流式 `clamp()` 标题。
- 全局 UI 字体使用同一 sans-serif 栈；阅读正文可以在内容容器内使用 serif。
- 页面标题、正文、标签、辅助文字和数据使用统一字号与行高 token。
- 主内容根据页面原型设置最大宽度；禁止页面通过负边距或壳层覆盖获得宽度。
- 文本缩放到 200% 时导航和关键操作仍可用，不出现水平滚动。

## 11. 渐进增强与错误处理

- 无 JavaScript：`shell-enhanced` 不存在，移动端不启用 fixed/transform 抽屉；核心导航在页面顶部按普通文档流显示，分类默认展开，可选入口维持基础 `hidden`，当前页面由服务端/静态 HTML 标记。
- localStorage 不可用或数据损坏：安全回退到桌面展开态，不阻塞导航。
- 图标资源失败：链接可访问名称和文字仍能表达目的。
- 浏览器不支持 `color-mix`：核心产品 token 使用明确颜色值，不依赖它生成必要对比。
- 动画和抽屉脚本异常：基础页面仍可通过常规链接导航。

## 12. 测试策略

### 12.1 静态契约

- 共享导航数据只有一个权威定义。
- 每个生产页面包含相同的导航 href、标签、SVG 图标和分类顺序。
- 页面 CSS 不包含禁止的裸元素规则或共享壳层选择器。
- 所有共享 CSS/JS 使用统一版本占位符或生成结果。
- `ui-features.js` 包含完整且唯一的 feature ID 集合，所有值必须是布尔值；`trend_radar` 首轮默认 `false`。
- 每个可隐藏入口都引用已配置的 feature ID，并带基础 `hidden`；侧栏、首页和快捷入口中不得使用散落的隐藏常量。
- 所有生产页面先加载带统一版本的 `ui-features.js`，再加载 `app-shell.js`；service worker 同步更新该配置资源。

### 12.2 JavaScript 单元测试

- 路由与 active 项匹配。
- 旧持久化状态迁移。
- 分类折叠、图标栏切换和异常存储回退。
- 已显式保存为 `false` 的当前分类不会被自动展开或改写；没有显式值时当前分类默认展开。
- ARIA 属性、焦点恢复与 Escape 行为。
- `true` 只展示对应入口，`false`、缺失和非法值保持隐藏；脚本不写 localStorage，也不请求后端配置 API。
- 初始 DOM 和页面加载后动态插入的 `[data-feature][hidden]` 使用同一判断结果；MutationObserver 不因无关 DOM 更新触发全页重扫。

### 12.3 UI 功能展示契约

- 参数化测试逐个切换 9 个 feature，断言对应侧栏、图标栏、移动抽屉、首页和快捷入口同步展示或隐藏。
- 浏览器测试在页面完成加载后动态插入一个带 `data-feature` 和 `hidden` 的快捷入口，分别断言 `true` 时自动展示、`false` 时保持隐藏。
- 关闭 `trend_radar` 后直接访问 `/trend-radar` 及调用 `/api/trend-radar/**` 的现有行为不变，证明没有误加后端门禁。
- 配置资源缓存版本变化时，页面加载新的布尔值，不继续使用旧 service worker cache。

### 12.4 浏览器契约

至少覆盖：

- 路由：主页、系列学习、图解生成、边播边学、心流阅读、心流写作、帖子洞察、趋势雷达、IP 对标、历史、设置、结果模板代表页。
- 视口：1440×1000、1024×768、390×844。
- 主题：light、dark。
- 状态：expanded、rail、分类折叠、移动抽屉打开/关闭。
- 断言：关键计算样式一致、44×44 目标、active 项、菜单可见、无横向溢出、键盘焦点顺序。
- 功能展示：趋势雷达为 `false` 时在桌面展开、图标栏、移动抽屉、首页和快捷入口中均不可见；改为 `true` 后刷新新版本资源即可恢复，直接 URL 始终保持可访问。
- 渐进增强：390×844 禁用 JavaScript 时，侧栏不在屏幕外，核心链接可见、可聚焦并可正常跳转，可选入口不泄漏。
- PWA：配置资源版本更新后受控客户端不继续使用旧布尔配置。

### 12.5 视觉回归

- 每种页面原型保存一个代表路由截图，而不是为所有相似页面创建大量脆弱快照。
- 重点比较应用壳层、页面背景、标题区、主要控件和状态组件。

## 13. 实施边界与顺序

按以下顺序实施：

1. 建立会失败的跨路由壳层和页面 CSS 边界契约。
2. 建立 `ui-features.js` 布尔配置和入口标记契约，不修改后端 API。
3. 收敛产品 token 与 `app-shell.css`，保持页面业务 DOM 不变。
4. 将 `app-shell.js` 改为渐进增强，接入 A+ 行为、功能入口过滤和状态迁移。
5. 修复心流阅读移动入口、心流写作特殊默认和趋势雷达样式泄漏。
6. 按四种页面原型逐页删除壳层覆盖、独立背景和独立强调色。
7. 统一资源版本并更新相关静态契约。
8. 执行单元、UI 功能开关、跨路由浏览器、明暗主题、移动端和视觉回归验证。

不在本次范围：

- 修改任何后端业务流程、路由、API 数据模型、鉴权或授权。
- 重写现有页面 JavaScript 功能模块。
- 引入新的前端框架、CSS-in-JS 或第三方组件库。
- 重做营销落地页；营销页面可以继续使用独立品牌表达，但进入产品后的壳层必须统一。
- 未经授权的提交、推送或部署。

## 14. 风险与控制

- 当前工作区存在大量未提交修改。实施必须只改与统一壳层相关的行，并在每批修改前后检查差异，避免覆盖用户工作。
- 静态 HTML、Jinja 与内联首页混合使单一渲染受限；首轮用共享导航数据、确定性同步和契约测试保持一致，避免引入前端构建框架或改动后端服务方式。
- 页面 CSS 规模较大，不能一次性全局替换。先建立禁止越界测试，再按页面原型分批迁移。
- 视觉一致性不能只靠字符串测试。必须保留浏览器计算样式和代表截图作为决定性证据。
- UI 功能开关有意不阻止直接 URL 或 API；文档和代码注释必须明确它不是安全控制，避免未来被误用为权限机制。
- `ui-features.js` 是缓存敏感资源；修改布尔值时必须同步资源版本和 service worker cache name，否则已安装客户端可能继续显示旧入口。
